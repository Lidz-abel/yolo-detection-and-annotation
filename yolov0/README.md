# yolov0

`yolov0` 是从 `miniyolo` 过渡到正式检测工程的新训练项目。

目标不是继续维持“极简可跑通”状态，而是逐步把模型、损失函数、训练监控和对比实验推进到“真正可用”的方向，同时保留 `miniyolo` 阶段已经建立起来的良好习惯：

- 训练配置不硬编码，统一由配置文件驱动
- 每次训练都保存结果文本、配置快照和模型权重
- 每次训练都记录 TensorBoard 指标
- 每个实验都要能回溯到具体 Git commit
- 报告中的结论必须建立在可复现结果之上

## 当前阶段核心任务

1. 逐步进化 backbone  
   从 `miniyolo` 的极简 CNN 出发，逐步加深网络，逐步引入残差连接等工程结构，最终逼近 `YOLOv5s-small` 或 `ResNet-18` 量级。

2. 补全检测损失  
   在现有分类 + bbox 回归损失基础上，加入：
   - objectness / no-objectness
   - 多类别分类损失
   - GIoU

3. 做受控对比实验  
   对比不同 backbone/模型配置的：
   - 参数量
   - 训练时间
   - 收敛速度
   - 最终 mAP
   - 推理 FPS

4. 给出保守可用配置  
   即使某些调参失败，也至少要产出一组“效果一般但可用”的：
   - 模型结构
   - 损失函数
   - 优化器
   - 学习率与调度器
   - 数据增广

## 目录结构

- `configs/`：训练、评估、实验配置
- `data/`：Dataset、target assignment、augmentation、sampler
- `models/`：backbone、neck、head、模块组件
- `losses/`：完整 YOLO 风格损失
- `engine/`：训练、验证、推理循环
- `utils/`：配置读取、日志、指标、可视化、性能统计
- `tools/`：命令行入口脚本
- `runs/`：TensorBoard 日志
- `outputs/`：模型权重、预测图、导出曲线
- `logs/`：实验记录、结果文本、材料汇总
- `report/`：LaTeX 报告

## 当前阶段推荐推进顺序

1. 先搭工程骨架与配置系统
2. 先做一版保守可用训练基线
3. 再逐步升级 backbone
4. 再补全完整 YOLO loss
5. 最后做对比实验和报告整理

## 当前阶段约定

- 正式训练默认优先使用 `Unified` 整理后的统一数据入口
- 训练应尽量利用服务器资源，但必须以“稳定可复现”为前提
- 所有阶段性实验结果都要写入 `logs/`，不要只停留在终端输出
- 每次实验都必须能回溯到配置快照、结果文本和 Git commit
